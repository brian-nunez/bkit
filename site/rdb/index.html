bkit / rdb

rdb

One API over relational databases.

Open any supported database from a URL or typed config struct, run queries with ? placeholders, scan rows into structs, run transactions, apply schema migrations, and match errors the same way on every database. Each driver is a separate module so an application installs only the drivers it uses.

Usage

Opening by URL or Config

Pass the drivers the application supports to rdb.Open. The URL scheme selects one driver, and only that driver connects. Every driver also provides a typed Open(ctx, Config{...}) constructor.

Open by URL / go 
db, err := rdb.Open(ctx, os.Getenv("DATABASE_URL"),
	sqlite.Driver(),
	postgres.Driver(),
	rdb.WithMaxOpenConns(25),
)
if err != nil {
	return err
}
defer db.Close()

Queries and strict scanning

rdb.One[T], rdb.All[T], and rdb.Each[T] scan rows into structs or scalar values. Struct fields match by db:"name" tag or field name (ignoring case and underscores, so CreatedAt matches created_at). Unmatched columns return rdb.ErrScan unless rdb.WithoutStrictScan() is set.

Query and scan rows / go 
type User struct {
	ID        int64  `db:"id"`
	Email     string `db:"email"`
	CreatedAt time.Time
}

user, err := rdb.One[User](ctx, db,
	"SELECT id, email, created_at FROM users WHERE email = ?", email)

for user, err := range rdb.Each[User](ctx, db, "SELECT id, email, created_at FROM users") {
	if err != nil {
		return err
	}
	process(user)
}

Placeholders and transactions

Write ? for every parameter. Use db.Raw() or tx.Raw() to send a single query without placeholder rewriting (for example, PostgreSQL jsonb ? operators). db.Tx commits when the callback returns nil and rolls back on error or panic.

Run a transaction / go 
err := db.Tx(ctx, func(tx *rdb.Tx) error {
	_, err := tx.Exec(ctx, "UPDATE accounts SET balance = balance - ? WHERE id = ?", amount, from)
	if err != nil {
		return err
	}
	_, err = tx.Exec(ctx, "UPDATE accounts SET balance = balance + ? WHERE id = ?", amount, to)
	return err
}, rdb.Isolation(sql.LevelSerializable))

Migrations

Keep migrations as .sql files and apply them at startup with db.Migrate. Migrate applies every pending migration in version order, records each one in the rdb_migrations table, and returns the migrations it applied. It reads the root of the file system, so use fs.Sub for a subdirectory. Running it again applies only new files. db.MigrationStatus(ctx, migrations) returns every migration with AppliedAt set on those that have run, without changing the database.

Apply embedded migrations / go 
//go:embed migrations/*.sql
var files embed.FS

migrations, err := fs.Sub(files, "migrations")
if err != nil {
	return err
}
applied, err := db.Migrate(ctx, migrations)

File names and statements

A file name is a positive version number, an underscore, a name of letters, digits, _, and -, an optional dialect (sqlite, postgres, or mysql), and .sql. A dialect file such as 0001_create_users.postgres.sql runs on that dialect in place of the plain file. Statements end at semicolons outside quotes and comments, and each one is sent without placeholder rewriting. Wrap a statement whose body contains semicolons, such as a trigger, between -- rdb:begin-statement and -- rdb:end-statement.

Multi-statement trigger directive / sql 
CREATE TABLE users (id INTEGER PRIMARY KEY, email TEXT NOT NULL);

-- rdb:begin-statement
CREATE TRIGGER users_audit AFTER INSERT ON users
BEGIN
  INSERT INTO audit (user_id) VALUES (NEW.id);
END;
-- rdb:end-statement

Transactions, locking, and history

SQLite and Postgres apply each migration and its history row in one transaction. MySQL and MariaDB commit schema changes as they run, so a migration there, or a file starting with -- rdb:no-transaction on any database, is recorded as dirty before it starts and marked finished at the end. A dirty migration stops later runs with ErrMigrationDirty. Concurrent instances take turns using an advisory lock on Postgres, GET_LOCK on MySQL and MariaDB, and the database write lock on SQLite. Use rdb.MigrationTable(name) to store history in another table.

Pool options and errors

WithMaxOpenConns, WithMaxIdleConns, WithConnMaxLifetime, WithConnMaxIdleTime, WithWarmConns, WithPool(rdb.Pool{...}), WithConnInit, WithConnectTimeout, WithOpenRetry, WithOpenTimeout, WithoutRebind(), and WithoutStrictScan().

Match with errors.Is: ErrNotFound (also matches sql.ErrNoRows), ErrUniqueViolation, ErrForeignKeyViolation, ErrNotNullViolation, ErrCheckViolation, ErrRetryable, ErrScan, ErrUnknownDriver, ErrInvalidURL, ErrInvalidOption, ErrInvalidMigration, ErrMigrationChanged, ErrMigrationMismatch, and ErrMigrationDirty. Error messages never contain the database URL or credentials.

Sentinel Meaning
ErrNotFound One found no rows. Also matches sql.ErrNoRows
ErrUniqueViolation A duplicate value in a unique index or primary key
ErrForeignKeyViolation A write that breaks a foreign key
ErrNotNullViolation A null in a NOT NULL column
ErrCheckViolation A write that fails a CHECK constraint
ErrRetryable A deadlock, serialization failure, or locked database
ErrScan Rows that cannot be scanned into the requested type
ErrUnknownDriver No driver matches the URL's scheme
ErrInvalidURL The URL cannot be parsed or has no scheme
ErrInvalidOption An option is out of range or conflicts
ErrInvalidMigrationA file name is invalid, a version has duplicate or missing dialect files, a directive is misused, or there are no files
ErrMigrationChangedAn applied migration file changed
ErrMigrationMismatchAn applied migration is missing from the files, or a pending file sorts before an applied one
ErrMigrationDirtyA migration started and did not finish

Driver setup

sqlite

Enables foreign keys, a 5-second busy timeout, and WAL on files. An in-memory database is limited to one connection and keeps its data until the rdb.DB is closed, even when the pool replaces the connection. rdb.Isolation accepts every level up to sql.LevelSerializable, including sql.LevelSnapshot. sql.LevelWriteCommitted and sql.LevelLinearizable fail.
